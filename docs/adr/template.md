# ADR-NNN: Decision title

- Status: Proposed
- Date: YYYY-MM-DD
- Owner issue: a link to the roadmap issue that owns this decision
- Guide: links to the guide sections this decision implements or changes
- Supersedes: links to the RFCs or ADRs this decision replaces, or "none"

## Context

State the problem, the constraints, and the guide requirements that force a decision. Cite code by file and symbol.

## Decision

State the choice as numbered, testable rules. Use present tense.

## Consequences

List what becomes easier, what becomes harder, and which follow-up issues own the remaining work. Name every guide section that must change.

## Alternatives considered

For each rejected option, give the reason it lost. Cite benchmark or prototype evidence where the decision depends on it.

## Verification

Give the commands or tests that show the decision holds, and say how a reviewer can falsify it.

## References

Link the guide sections, RFCs, issues, and external sources used.
