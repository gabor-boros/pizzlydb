## Summary

Turn the `pizzlydb` binary into the single operator entry point. It provides four groups of commands:

- **Server:** `serve` starts the server ([202](202-server-runtime.md)).
- **Remote admin** through the SDK and the admin API: `backup`, `restore`, `verify`, `jobs`, `namespaces`, `tenants`, `roles`, `credentials`, `subscriptions`, `retention`, `diagnostics`, and `config`.
- **Offline tools** that open a stopped data directory directly, read-only unless the action requires writes ([015](015-exclusive-ownership-and-read-only-open.md)): `offline verify`, `offline salvage`, `offline upgrade`, `offline bulk-load`, `offline export` and `offline import`, `offline inspect`, and `audit verify`.
- **Query shell:** an interactive shell with history, parameters, explain, and output formats (table, JSON, and JSON lines).

## Motivation

The release workflow already packages `pizzlydb-cli` as the shipped artifact, but `main()` is empty. Operators need tools that work when the server is down. Bulk load and offline verify are guide requirements ([110](110-bounded-memory-bulk-loader.md), [107](107-full-verification-and-online-scrubbing.md)).

## Current State

- `crates/pizzlydb-cli/src/main.rs` contains `fn main() {}` with the doc comment "The shell does not open a database yet".
- `.github/workflows/release-please.yml` builds and attests Linux x86-64 and aarch64 archives of this binary.

## Scope

### In scope

- **Argument parsing** with `clap`, with consistent exit codes (0 for success, 1 for operational failure, 2 for usage, and 3 for detected corruption), machine-readable output (`--output json`), and shell completions.
- **Connection profiles** that combine endpoint, TLS, and credentials, with no secrets on the command line. Credentials come from files, environment variables, or the secret provider ([210](210-secrets-management.md)).
- **Safety on destructive commands:** confirmation prompts, `--yes`, and dry-run by default. Offline commands refuse to run against a data directory that is locked by a running server.
- **Query shell:** multi-line editing, parameter binding, and `\explain`, with no string interpolation into queries.

### Out of scope

- A graphical UI.
